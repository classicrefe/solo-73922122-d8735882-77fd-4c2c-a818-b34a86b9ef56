# 循环泵累计故障率核算台（Flask + SQLite）

面向维护班组与失效分析员的网页工具：上传每泵一行的台账 CSV，按累计运行
小时计算**故障累计发生率（Aalen–Johansen 竞争风险累积发生率，CIF）**，
支持任意小时查询、单泵记录更正，并为失效分析员生成**故障泵–对照泵 1:1
配对名单**。台账、汇总与名单在同一 SQLite 事务内生效。

## 0. 配对名单功能（失效分析员成对调阅）

在「配对名单」页（`/roster`）从台账勾选**最多 20 台故障泵**与**最多 60
台候选对照泵**，填写两泵**入册工时允许相差的上限**，保存一份现行名单。

### 对照泵合格条件（同时满足）

1. 对照泵在故障工时（故障泵出册小时 t）**已入册**：`入册(c) ≤ t`；
2. 对照泵**出册在 t 之后**，或**恰在 t 结束观察**
   （`出册(c) > t`，或 `出册(c) = t` 且结束方式为观察结束）；
3. 两泵入册工时差不超过上限：`|入册(f) − 入册(c)| ≤ 上限`；
4. 已选故障泵不可作对照；每台对照最多使用一次（1:1）。

### 优化目标（最小费用最大流，见 `app/matching.py`）

1. **先让尽可能多的故障泵配到对照**（最大基数匹配）；
2. 基数相同时，**保留最多的上次配对**（次目标）；
3. 再按入册工时差、泵号做与输入顺序无关的确定性决胜，重跑结果一致。

### 更正与重传后的行为

- 单泵更正或整表重传后，系统在**同一事务内按原选泵号与工时差上限自动
  重算名单**，不需要重新勾选；
- 原选故障泵在页面分别标明：**已配对 / 尚未配到对照 / 已改为非故障 /
  缺记录**（台账中已无该泵号）；候选对照缺失或被占用同样标注；
- 任何写入失败一律 `ROLLBACK`，**台账、汇总、名单全部沿用原数据**。

## 1. 计算口径（与需求逐条对应）

每条记录：泵号、入册累计运行小时、出册累计运行小时、结束方式
（`failure` 故障 / `preventive` 预防更换 / `censored` 观察结束）。

对每个不同的运行小时时点 t，严格按以下顺序处理：

1. **先计入新入册的泵**（延迟进入风险集）；
2. 用**当时在册数 n(t)** 计算两类事件的风险率：
   - 故障风险率 `h_f(t) = d_f(t) / n(t)`
   - 预防更换风险率 `h_p(t) = d_p(t) / n(t)`
3. **移除所有出册泵**（故障、预防更换、观察结束都退出风险集）。

累计故障率按**此前未发生两类事件的概率 S(t⁻) 加权累加**（预防更换为
竞争事件，观察结束只退出风险集、不带事件概率）：

```
S(t)   = Π_{u≤t} (1 − d_f(u)/n(u) − d_p(u)/n(u))
F_f(t) = Σ_{u≤t} S(u⁻) · d_f(u)/n(u)      # 累计故障发生率
F_p(t) = Σ_{u≤t} S(u⁻) · d_p(u)/n(u)      # 累计预防更换率
恒等式：S(t) + F_f(t) + F_p(t) = 1
```

任意小时查询取不晚于该小时的最近时点值（阶梯函数），并返回该时点的
逐时点计数（入册、在册 n、故障 d_f、预防 d_p、观察结束 d_c 等）。

## 2. 数据与事务保证

SQLite 七张表（见 `app/db.py`）：

| 表 | 内容 |
|---|---|
| `ledger` | 泵台账，泵号主键，含入/出册小时、结束方式、更新时间 |
| `life_table` | 汇总：每个时点一行，逐时点计数、风险率、S、F_f、F_p |
| `meta` | 泵总数、汇总/名单更新时间、最近数据来源 |
| `roster_spec` | 现行名单参数（单行）：入册工时差上限、更新时间 |
| `roster_failures` | 名单所选故障泵及勾选顺序 |
| `roster_candidates` | 名单所选候选对照泵及勾选顺序 |
| `roster_pairs` | 最近一次配出的对子（供下次重算的保留决胜） |

- 上传 CSV = 整体替换台账；单泵更正 = upsert 一行；保存名单 = 写入
  勾选与工时差上限并跑一次匹配。三条写路径都在**一个事务**内完成
  「写台账/名单 → 重算并替换汇总 → 重算配对名单」，任何一步失败即
  `ROLLBACK`，**保留原有台账、汇总与名单**（`app/services.py`）。
- 单泵更正只需提交该泵数据，服务端自行从库内加载全量台账重算汇总与
  名单，**无须读取/回传其他泵明细**。
- 查询接口（`/query`、`/api/query`、`/api/lifetable`、`/api/roster`、
  `/roster` 展示）只读，不执行任何写操作。

## 3. 目录结构

```
app/
  __init__.py     Flask 路由（上传、台账、更正、名单、查询、JSON API）
  lifetable.py    生命表/CIF 纯计算与校验
  matching.py     配对资格判定 + 最小费用最大流匹配（基数优先、保留次之）
  csvio.py        CSV 解析（中英文表头、三种结束方式别名、逐行报错）
  db.py           SQLite 连接与建表
  services.py     事务服务层（替换台账、单泵 upsert、名单保存与重算、只读查询）
  templates/      5 个 Jinja 页面
  static/style.css
tests/test_app.py    20 个 unittest 用例（数学、边界、CSV、事务回滚、网页、只读性）
tests/test_roster.py 21 个 unittest 用例（资格、优化目标、事务、名单网页、更正重算）
sample/pumps_sample.csv             示例台账（6 台故障泵 + 12 台候选对照）
sample/pumps_sample_corrected.csv   更正版台账（F3 改预防更换、删除 C3），用于网页演示
Dockerfile, docker-compose.yml, requirements.txt, wsgi.py
```

## 4. 用 Docker Compose 启动

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

- 数据库在命名卷 `pump_data` 内（容器路径 `/app/instance/pumps.db`），
  重建容器数据不丢；健康检查 `GET /health`。
- 生产环境请通过环境变量 `FLASK_SECRET_KEY` 改密钥。

停止：`docker compose down`（保留数据卷）；连数据一起清除：
`docker compose down -v`。

## 5. 本地直接运行（无 Docker 时）

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python wsgi.py                      # 或 gunicorn wsgi:app
```

## 6. 网页试用流程（含更正后名单演示）

1. 首页「上传 CSV」选择 `sample/pumps_sample.csv`（18 台：6 台故障泵
   F1–F6、12 台候选对照 C1–C12；表头支持
   `泵号/入册累计运行小时/出册累计运行小时/结束方式`，结束方式填
   `故障/预防更换/观察结束`，也接受英文 failure/preventive/censored；
   编码支持 UTF-8 与 GBK）。
2. 打开「配对名单」页，工时差上限填 `500`，勾选全部 F1–F6 为故障泵、
   C1–C12 为候选对照，保存 → 得到 6 对，首次保存「保留上次配对」为 0。
   再点一次保存（不改选择）→ 6 对全部标记为「保留」。
3. 打开「台账」，把 **F3 更正为预防更换**（入册 500、出册 2500、结束
   方式选预防更换）保存。回到配对名单：F3 标注「已改为非故障」，
   其余 5 对全部保留，页面顶部统计实时更新。
4. 首页上传 **`sample/pumps_sample_corrected.csv`**（整表重传：F3 已为
   预防更换，且 C3 已从台账删除）。名单按原选泵号与 500 上限自动重算：
   F3 标「已改为非故障」、候选 C3 标「缺记录」，5 对保留。
5. 「故障率查询」输入任意小时（如 1500、2000），得到累计故障率、
   累计预防率、无事件概率及该结果使用的逐时点计数。生命表手算练习可用
   `sample/lifetable_demo.csv`（6 台泵，见第 8 节基准）。

JSON 接口：

```bash
curl 'http://localhost:8000/api/query?hours=2000'
curl 'http://localhost:8000/api/lifetable'
curl 'http://localhost:8000/api/roster'        # 未保存名单时返回 404
```

## 8. 示例数据的手算基准（sample/lifetable_demo.csv，6 台泵）

| t | 入册 | n(t) | d_f | d_p | d_c | S(t) | F_f(t) | F_p(t) |
|---|---|---|---|---|---|---|---|---|
| 0 | 4 | 4 | 0 | 0 | 0 | 1.0000 | 0.0000 | 0.0000 |
| 500 | 1 | 5 | 0 | 0 | 0 | 1.0000 | 0.0000 | 0.0000 |
| 1000 | 1 | 6 | 1 | 1 | 0 | 0.6667 | 0.1667 | 0.1667 |
| 2000 | 0 | 4 | 1 | 0 | 1 | 0.5000 | 0.3333 | 0.1667 |
| 3000 | 0 | 2 | 0 | 1 | 1 | 0.2500 | 0.3333 | 0.4167 |

末时点 `S + F_f + F_p = 0.25 + 0.3333 + 0.4167 = 1`。
